4.1 Introduction to Software Design 
This chapter presents the detailed software design of the Ghost Interview AI Mock 
Interviewer system. It translates the requirements identi ed in Chapter 3 into structured 
architectural, behavioral, and data models. The purpose of this chapter is to provide a clear 
blueprint for system implementation, ensuring maintainability, scalability, and modular 
development. 
This chapter includes architectural design, UML models, data ow models, and database 
design for the Ghost Interview web-based AI application. The system integrates multiple AI 
services including OpenAI Whisper, Gemini API, DeepFace/Hume AI, and ElevenLabs to 
deliver a comprehensive mock interview experience. 
4.2 Design Methodology and Software Process Model 
4.2.1 Design Methodology 
This project fol lows the Object -Oriented Design (OOD) methodology combined with a 
Layered Architecture approach. This methodology is selected due to the following reasons: 
Modularity: Each system module (User Management, AI Interview, Speech Analysis, 
Emotion Detection, Reporting) is developed as an independent, reusable component. 
Scalability: The layered architecture allows each tier (frontend, backend, AI services) 
to be scaled independently based on load. 
Loose Coupling: AI service integrations (Whisper, Gemini, ElevenLabs, DeepFace) are 
loosely coupled through API abstraction layers, allowing easy replacement or 
upgrade of individual services. 
Reusability: Common components such as authentication, session management, and 
report generation are reused across modules. 
The design follows key principles including SOLID, DRY (Don’t Repeat Yourself), and 
Separation of Concerns, ensuring clean and maintainable code architecture.

4.2.2 Software Process Model 
The project follows the Agile Incremental development model. This model  is selected for 
the following reasons: 
The system integrates multiple AI APIs whose behavior may require iterative re 
nement based on real testing results. 
Features such as emotion detection accuracy and speech analysis quality need 
continuous evaluation and improvement cycles. 
Agile allows the team to deliver working modules incrementally: rst user 
management, then the interview engine, then analysis modules, and nally the 
reporting dashboard. 
Testing and validation are integrated at the end of each sprin t, reducing late -stage 
defect discovery. 
Development Phases / Sprints: 
1. Sprint 1: User registration, login, and dashboard setup. 
2. Sprint 2: Job role selection and Gemini API interview question integration. 
3. Sprint 3: AI avatar voice interaction using ElevenLabs and WebRTC. 
4. Sprint 4: Speech-to-text conversion (Whisper) and ller word detection. 
5. Sprint 5: Emotion detection (DeepFace/Hume AI) and sentiment analysis. 
6. Sprint 6: Con dence & Competency Report generation and interview history 
dashboard. 
7. Sprint 7: Testing, optimization, and nal deployment.

4.4 Architectural Design 
This section describes the high-level three-tier architecture of the Ghost Interview system. 
The system is divided into the following layers: 
Presentation Layer (Frontend): Built using React.js (v18+). Handles all user interface 
components including login, job role selection, interview screen (webcam + avatar), 
and report dashboard. WebRTC is used for real-time webcam and microphone access. 
Business Logic Layer (Backend): Built using Node.js (v20+). Handles session 
management, API orchestration, speech analysis pipeline, emotion data aggregation, 
and report computation. RESTful APIs are exposed to the frontend. 
AI Services Layer: Comprises four external AI APIs: 
Gemini API Interview question generation.

OpenAI Whisper Speech-to-text conversion. 
DeepFace / Hume AI Facial emotion detection. 
ElevenLabs AI voice synthesis for avatar. 
Data Layer (Database): Stores all persistent data including user accounts, interview 
sessions, transcripts, emotion metrics, and generated reports. A NoSQL database 
(e.g., MongoDB) is preferred for its exibility with session and report data structures.

over HTTPS. The backend orchestrates calls to the four AI service APIs, processes responses, 
and stores results in the database. All API keys are stored server-side for security. WebRTC 
streams webcam and audio data directly in the browser, which is then captured and 
forwarded to the backend for processing.

One-to-One (1:1): One InterviewSession generates exactly one Report. 
Many-to-One (N:1): Many InterviewSessions may use the same JobRole.

4.9.4 Security and Data Integrity 
To ensure con dentiality and integrity of stored data, the following measures are 
implemented: 
Password Encryption: Passwords are hashed using bcrypt before storage. 
Role-Based Access Control (RBAC): Admins and Candidates have distinct access 
privileges enforced at the API layer. 
Input Validation: All user inputs are validated both client-side and server-side before 
database operations. 
HTTPS Communication: All data transmission between client and server uses HTTPS 
encryption. 
API Key Security: Third -party API keys (Gemini, Whisper, ElevenLabs, DeepFace) are 
stored as server-side environment variables and never exposed to the client. 
Database Backup: MongoDB Atlas provides automated daily backups and point -in-
time recovery. 
4.9.5 Scalability Considerations 
The database design incorporates scalability mechanisms to support future growth: 
Horizontal Scaling: MongoDB Atlas supports sharding for distributing large datasets 
across multiple nodes. 
Indexing: Indexes on user_id, session_id, and created_at improve query performance 
for dashboard and report retrieval. 
Caching: Frequently accessed data such as job role lists can be cached using Redis to 
reduce database load. 
Load Balancing: The Node.js backend can be deployed across multiple instances 
behind a load balancer for high availability.
