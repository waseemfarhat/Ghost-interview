3.1 Introduction to Requirement Analysis 
This chapter presents a structured and formal speci cation of sys tem requirements for 
Ghost Interview AI Mock Interviewer. The purpose of this chapter is to clearly de ne what 
the system shall accomplish before proceeding to the system design phase. The 
requirements documented here serve as a contractual foundation for implementation, 
validation, and system testing. 
The requirement analysis includes requirement elicitation techniques, identi cation of 
stakeholders, use case modeling, functional requirements, non -functional requirements, 
and external interface requirement s. All requirements are written in measurable and 
testable format using standard requirement engineering principles.

Stakeholder Interviews: To capture user expectations and constraints from students, 
job seekers, and supervisors.

and interview preparation systems.

3.4 System Overview 
The proposed system operates within a three -tier web architecture designed to support 
modular interaction between user int erfaces, backend processing logic, AI services, and 
data storage. The system supports role -based interactions and ensures secure 
communication between internal modules and external AI services. 
The system boundary includes: 
React.js-based frontend (user interface and webcam/microphone interaction). 
Node.js backend (business logic, API orchestration, session management). 
AI processing layer (speech -to-text, emotion detection, language model, voice 
synthesis). 
Database (user data, interview sessions, reports).

3.7 Non-Functional Requirements 
Non-functional requirements de ne quality attributes that describe how the system 
performs. These requirements are measurable and support system reliability, usability, 
performance, security, and maintainability. 
3.7.1 Performance Requirements 
PER-1: The system shall load the main dashboard within 3 seconds under normal 
operating conditions. 
PER-2: Speech -to-text transcription responses from OpenAI  Whisper shall be 
returned within 5 seconds of audio submission. 
PER-3: Emotion detection results shall be processed within 2 seconds per video frame 
batch. 
PER-4: The system shall handle at least 50 concurrent interview sessions without signi 
cant degradation in response time. 
Ghost Interview AI Mock Interviewer SRS Document 
13 
PER-5: The AI avatar’s rst question shall be delivered within 3 seconds of the interview 
session start. 
3.7.2 Security Requirements 
SEC-1: The system shall implement secure user authentication using hashed 
passwords (e.g., bcrypt). 
SEC-2: All data transmission shall use HTTPS protocol to ensure encryption in transit. 
SEC-3: Webcam and microphone access shall require explicit user permission via 
browser consent prompts. 
SEC-4: Role-based access control shall be enforced (Admin vs Candidate). 
SEC-5: API keys for third-party services shall be stored server-side and never exposed 
to the client. 
SEC-6: User interview recordings and session data shall be stored securely and not 
shared with third parties. 
3.7.3 Reliability Requirements 
REL-1: The system shall maintain at least 99% uptime during the evaluation period. 
REL-2: System failures shall not result in loss of completed interview session data. 
REL-3: The system shall implement error handling for third -party API unavailability 
and notify users gracefully. 
REL-4: Backup and recovery mechanisms shall be implemented for the database. 
3.7.4 Usability Requirements 
USE-1: The interface shall be intuitive and easy to navigate without prior training. 
USE-2: Clear and meaningful error messages sha ll be displayed for all failure 
scenarios. 
USE-3: The system shall follow standard UI/UX design principles and be visually 
appealing. 
USE-4: The application shall be fully responsive across desktop and laptop screen 
sizes. 
USE-5: The AI avatar interaction interface shall clearly indicate when the avatar is 
speaking and when the user is expected to respond.

3.7.5 Scalability Requirements 
SCA-1: The system architecture shall support increasing number of registered users 
and concurrent sessions. 
SCA-2: The backend shall allow horizontal scaling through cloud deployment. 
SCA-3: The database design shall support large volumes of session transcripts and 
report data. 
SCA-4: New job roles and interview categories shall be addable without major 
restructuring. 
3.7.6 Maintainability Requirements 
MAIN-1: The system shall follow modular architecture principles with clearly 
separated frontend, backend, and AI service layers. 
MAIN-2: Source code shall be documented clearly using inline comments and 
README les. 
MAIN-3: Futur e updates, including additional AI models or job roles, shall be 
integrable without major system restructuring. 
MAIN-4: The system shall use version -controlled repositories (e.g., GitHub) for code 
management.

3.8.2 Hardware Interface Requirements 
HI-1: The system shall operate on standard computing devices (PC, laptop) with a

HI-2: The system requires access to a functional webcam and microphone for

HI-3: Minimum hardware: 4GB RAM, modern dual-core processor, HD webcam (720p

3.8.3 Software Interface Requirements 
SI-1: The system shall interact with a relational or non-relational database for storing 
user data, sessions, and reports. 
SI-2: The system shall integrate with the Gemini API for AI-driven interview question 
generation. 
SI-3: The system shall integrate with OpenAI Whisper API for speech -to-text 
conversion. 
SI-4: The system shall integrate with DeepFace / Hume AI for facial emotion 
detection. 
SI-5: The system shall integrate with ElevenLabs API for realistic AI voice synthesis. 
SI-6: The frontend shall be built using React.js (v18+) and the backend using Node.js 
(v20+). 
3.8.4 Communication Interface Requirements  
CI-1: The system shall use HTTPS protocol for all secure client-server communication. 
CI-2: RESTful APIs shall be used for backend communication between frontend and 
server. 
CI-3: WebRTC shall be used for real-time webcam and microphone access within the 
browser. 
CI-4: All third-party API calls shall be made server-side to protect API credentials.

3.9 Assumptions and Dependencies 
The system assumes stable internet connectivity for all users during interview 
sessions. 
Third-party services (Gemini, Whisper, DeepFace, ElevenLabs) are assumed to remain 
available and functional throughout the project. 
Users are assumed to possess basic digital literacy and be comfortable using web 
browsers. 
Required cloud hosting infrastructure is assumed to be available during deployment. 
Users are assumed to have access to a functional HD webcam and microphone. 
Pre-trained AI models will be used; no custom model training is assumed within 
project scope.
